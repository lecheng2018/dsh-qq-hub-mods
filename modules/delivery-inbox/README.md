# 投递异常（delivery-inbox）

只读查看「没送出去 / 不确定送达」的消息，是投递台账（`deliveries.json`）的排查出口。

- **只读，不提供重发**：`unknown` 的定义是「可能已经发出去了」，重发可能造成重复消息——要不要再发由人决定。
- **默认只看异常**：`unknown` / `failed` / `cancelled` 三类进列表，正常 `sent` 不掺进来。
- **读不到就说读不到**：文件缺失或损坏时明确报「读不到」，绝不伪装成「没有异常」。
- 内容只给前 60 字预览，够认出是哪条消息即可，不在面板摊全文。

## 它从哪读数据

台账由插件核心统一落盘在插件数据目录的 `deliveries.json`（Outbox 每次发送都记账：sent/failed/unknown/cancelled）。本模块经宿主的 `lib('core/store.js')` 读这个全局文件（只读）；`api.dataDir(...)` 是模块私有沙箱，读不到真台账，所以不走它。

## 使用

安装后面板「系统」分组出现「投递异常」页，展示：

- 状态（不确定送达 / 发送失败 / 被拦下）与各自含义
- 会话、发生时间、重试次数、发件方（core 或某个扩展模块）
- 正文预览、失败原因、备注

## 说明

- 本模块替代内置同名模块时，安装需在面板确认（replacesBuiltin 流程）；内置移除后是独立扩展模块，路由在 `/ext/delivery-inbox/` 下，面板调用自动适配。
- 卸载不影响投递本身——台账照常记录，只是没有这个查看出口。
